# wdxc — Milestone 0: Hello World With No libc

**Status:** complete
**Goal:** a program that prints a line and exits with status 0, linked against nothing but wdxc.

```
$ make test
== build/tests/hello
Hello from wdxc.v0.1!
```

---

## Project scope (decided before ml0)

wdxc is the C standard library for Midir Linux's own core userland. It is not trying to replace glibc or musl; those ship as an add-on toolchain for third-party packages.

| Decision | Choice | Why |
|---|---|---|
| Linking | Static only | No dynamic loader to write, no `LD_PRELOAD` / library hijacking |
| Architecture | x86_64 first | Everything CPU-specific lives in `arch/`, so a port only adds files there |
| Threads | Not yet | Midir's core tools are single-threaded. `errno` via a function and a single TLS block keep the door open |
| Security | Tiered | Cheap wins now (no `gets`/`sprintf`/`%n`), stack canaries + static-PIE next, hardened malloc after |
| Out of scope | Locales, wide chars, float `printf`, libm, DNS, `iconv`, `dlopen`, regex | The add-on toolchain covers these |
| Growth rule | A function is added only when a real Midir program needs it | Keeps "minimal" honest |

## What happens when the program runs

```
kernel ──► _start (crt1.S) ──► __start_c (start.c) ──► main (hello.c)
                                                          │
                                         write(1, msg, n) ◄┘
                                                 │
                                   __syscall3 (syscall_arch.h)
                                                 │
                                          kernel: sys_write
main returns ──► exit(status) ──► __syscall1(exit_group) ──► kernel ends process
```

The whole program makes exactly one syscall before exiting (`write`), versus a dozen-plus for a glibc hello world before `main` even starts.

```
│   ├── stdlib.h            exit
│   ├── string.h            strlen
│   └── unistd.h            write
├── src/                    portable C, one function per file
│   ├── env/start.c         __start_c
│   ├── exit/exit.c
│   ├── string/strlen.c
│   └── unistd/write.c
└── tests/hello.c
```

### The three layers

1. **`arch/`: how to talk to the kernel on this CPU.** Only this changes for an aarch64 port. Syscall numbers live here too, because they differ per CPU (`write` is 1 on x86_64, 64 on aarch64).
2. **`src/`: the libc API.** Plain C, identical on every CPU. `write()` is a one-line wrapper that passes its arguments to `__syscall3` with `SYS_write`.
3. **`include/`: what programs see.** Prototypes only. Each `.c` in `src/` includes its own header so the compiler catches any mismatch between prototype and definition.

## Concepts learned

### Programs don't start at `main`
The kernel jumps to the ELF entry point, `_start`. It has no caller, so returning from it crashes. `_start` must find the arguments, call `main`, and end the process with a syscall.

### The initial stack
At `_start`, `rsp` points at:

```
sp[0]           argc
sp[1..argc]     argv pointers
sp[argc+1]      NULL
sp[argc+2..]    envp pointers
                NULL
                auxv (type, value) pairs ... AT_NULL
```

`__start_c(long *sp)` turns this into `main(argc, argv, envp)`: `argc = sp[0]`, `argv = &sp[1]`, `envp = &sp[argc + 2]`.

### `_start`, line by line (AT&T syntax: source, destination)

| Line | Purpose |
|---|---|
| `xor %ebp, %ebp` | `rbp = 0`: marks the outermost frame for debuggers |
| `mov %rsp, %rdi` | Pass the stack pointer as `__start_c`'s first argument |
| `and $-16, %rsp` | Round down to a 16-byte boundary; the ABI requires it before any `call` |
| `call __start_c` | Enter C |
| `hlt` | Privileged instruction: if `__start_c` ever returns, the process dies instead of running garbage |
| `.section .note.GNU-stack` | Marks the stack non-executable. Without it the linker may make it executable, which exploits want |

### Two calling conventions
- **C functions:** arguments in `rdi, rsi, rdx, rcx, r8, r9`.
- **Syscalls:** number in `rax`, arguments in `rdi, rsi, rdx, r10, r8, r9`. It's `r10` instead of `rcx` because the `syscall` instruction overwrites `rcx` (and `r11`). Result comes back in `rax`; `-4095..-1` means `-errno`.

### GCC inline assembly
```c
__asm__ volatile ("syscall"
                  : "=a"(ret)                 /* outputs  */
                  : "a"(n), "D"(a)            /* inputs   */
                  : "rcx", "r11", "memory");  /* clobbers */
```
- Constraint letters pick registers: `a`=rax, `D`=rdi, `S`=rsi, `d`=rdx.
- `volatile` stops the optimizer from deleting a syscall whose result looks unused.
- `"memory"` tells the compiler the kernel may read or write memory, so buffers are fully written before the syscall.

### `exit` must never return
`exit_group` (231) ends the whole process; `exit` (60) only ends the calling thread. The kernel never returns from it, but the compiler can't know that, so `exit` is marked `_Noreturn` and wraps the syscall in `for (;;)`.

### One function per file
The linker pulls whole `.o` files out of `libwdxc.a`. Grouping 30 functions in one file would put all 30 in every program that uses one of them.

## Build

| Flag | Purpose |
|---|---|
| `-nostdlib` | Don't link glibc or its startup files |
| `-nostdinc` | Don't use host headers (this is why `#include <stdio.h>` failed: wdxc has no stdio yet) |
| `-ffreestanding` | Don't assume a hosted libc exists |
| `-fno-builtin` | Don't swap our functions for compiler builtins |
| `-fno-stack-protector` | Canaries need TLS, planned for ml3 |
| `-static -no-pie` / `-fno-pie` | Static, non-PIE for now; static-PIE planned for ml5 |

`crt1.o` is kept out of the archive and passed to the linker explicitly: nothing *calls* `_start`, so the linker would never pull it from `libwdxc.a` on its own.

All output is confined to `build/`:

```
build/
├── obj/      object files, mirroring the source tree
├── lib/      crt1.o, libwdxc.a
└── tests/    runnable test programs
```

`make` builds, `make test` builds and runs the tests, `make clean` removes `build/`. The Makefile doesn't track header changes yet, so run `make clean` after editing a `.h`.

## Problems hit along the way

| Problem | Cause | Fix |
|---|---|---|
| `exit` wouldn't compile | Copied the helper's `(long n, long a)` signature; passed `long error_code` (a declaration) in a call | `_Noreturn void exit(int status)`, pass `status` |
| `No rule to make target 'arch/x86_64/crt1.S'` | File was named lowercase `crt1.s` | Rename to `.S` so it goes through the C preprocessor |
| `stdio.h: No such file or directory` | `-nostdinc` correctly blocking glibc's header | Use wdxc's own `write` + `strlen` until ml2 adds stdio |

## Verification

```sh
./build/tests/hello; echo $?        # prints the message, then 0
file build/tests/hello              # "statically linked"
nm build/tests/hello | grep ' U '   # nothing: no undefined symbols
strace ./build/tests/hello          # execve, write, exit_group, and nothing else
```
